# S3 Upload with Presigned URL

A proof-of-concept demonstrating how to upload files directly to Amazon S3 using presigned URLs. The presigned URL is generated by a serverless API (API Gateway + Lambda) and returned to the client. The client then uploads directly to S3 — the file never passes through the backend.

## Architecture

```
Angular Frontend
      │
      ▼
API Gateway ──► Lambda (.NET 8) ──► generates presigned URL
                                          │
      ◄───────────────────────────────────┘
      │
      ▼
    S3 (direct upload via presigned URL)
```

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Backend | C# / .NET 8, ASP.NET Core Web API |
| Hosting | AWS Lambda + API Gateway |
| Storage | AWS S3 |
| Frontend | Angular 18, TypeScript, Tailwind CSS |
| Infrastructure | AWS SAM |

## API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/s3/get-presigned-url-upload` | Generate a presigned PUT URL for uploading |
| `POST` | `/api/s3/get-presigned-url-download` | Generate a presigned GET URL for downloading |
| `POST` | `/api/s3/delete-file` | Delete an object by key |
| `GET`  | `/api/s3/list-objects` | List all objects in the bucket |
| `GET`  | `/api/s3` | Health check — returns bucket name |

## Prerequisites

- [AWS SAM CLI](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html)
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- [Node.js](https://nodejs.org/) + [Angular CLI](https://angular.io/cli) (`npm install -g @angular/cli`)
- AWS credentials configured locally

## Deploy

```bash
sam build
sam deploy --guided
```

After deployment, note the API Gateway URL from the output:

```
-----------------------------
Key         BackendApi
Description API Gateway endpoint URL for Prod stage for BackendAPI function
Value       https://xxxxxxxx.execute-api.us-east-2.amazonaws.com/Prod/

Key         S3Bucket
Description S3 Bucket
Value       arn:aws:s3:::file-upload-demo-appbucket-xxxxxxxx
-----------------------------
```

Update `src/Frontend/src/config.ts` with the API Gateway URL:

```ts
const config = {
  api: "https://xxxxxxxx.execute-api.us-east-2.amazonaws.com/Prod/",
};
export default config;
```

## Run the Frontend

```bash
cd ./src/Frontend/
npm install
ng serve --open
```

## Teardown

```bash
sam delete
```

## TODO — Improvements

The following items represent known gaps and areas for improvement in this POC. Contributions are welcome.

### Security

- [ ] **Restrict CORS origins** — Both the API Gateway (`template.yaml`) and ASP.NET Core (`Startup.cs`) currently use `AllowAnyOrigin()` / `'*'`. In production, restrict to your frontend domain.
- [ ] **Scope IAM permissions** — The Lambda execution role grants `s3:*` on `*`. Replace with least-privilege: only the specific S3 actions needed (`s3:PutObject`, `s3:GetObject`, `s3:DeleteObject`, `s3:ListBucket`) scoped to the specific bucket ARN.
- [ ] **Add input validation** — The upload endpoint accepts any `FileType` and `FileName` without sanitisation. Validate MIME types and enforce an allowed file extension list.
- [ ] **Protect the API** — Add an API Gateway authoriser (e.g. Cognito User Pool, Lambda authoriser, or API key) so only authenticated users can generate presigned URLs.
- [ ] **Enable S3 bucket versioning** — Protect against accidental overwrites or deletions.
- [ ] **Enable S3 server-side encryption** — Enforce `aws:kms` or `AES256` encryption on the bucket.
- [ ] **Block public access on the S3 bucket** — The bucket should not need to be publicly accessible; presigned URLs provide time-limited access without making the bucket public.

### Code Quality

- [ ] **Remove unused dependencies** — `Startup.cs` imports and registers `IAmazonStepFunctions`, `IAmazonDynamoDB`, `StackExchange.Redis`, and `Amazon.ElastiCacheCluster` but none are used in the project. Remove them from both `Startup.cs` and `BackendAPI.csproj`.
- [ ] **Wire up the frontend upload flow** — `upload.component.ts` has the upload UI commented out and `onUpload()` points to `'your-api-endpoint'`. Implement the full presigned URL upload flow using `config.ts`.
- [ ] **Inject `IAmazonS3` via DI** — `S3Controller` creates a new `AmazonS3Client()` inside every method using `using` blocks. Register `IAmazonS3` as a singleton in `Startup.cs` and inject it through the constructor for testability and connection reuse.
- [ ] **Add error handling** — Wrap S3 API calls in try/catch blocks and return structured error responses (e.g. `ProblemDetails`) instead of letting unhandled exceptions bubble up.
- [ ] **Fix inconsistent indentation** — `ListObjects` method body has inconsistent indentation. Enforce an `.editorconfig` or run `dotnet format`.

### Testing

- [ ] **Add backend unit tests** — There are no tests for the .NET backend. Add an xUnit test project covering the controller methods with a mocked `IAmazonS3`.
- [ ] **Implement frontend component tests** — `upload.component.spec.ts` exists but contains only the scaffolded placeholder. Write tests for file selection, upload triggering, and error states.
- [ ] **Add integration/smoke tests** — Add a post-deploy test script that calls the health-check endpoint (`GET /api/s3`) to verify the stack is running correctly.

### Developer Experience

- [ ] **Add a local development guide** — Document how to run the backend locally using `LocalEntryPoint.cs` without needing to deploy to AWS (e.g. using environment variables or `launchSettings.json`).
- [ ] **Parameterise the SAM template** — Hard-coded values such as `us-east-2` and `file-upload-demo` should be SAM `Parameters` so the template is reusable across regions and environments.
- [ ] **Add environment-specific config** — Support `dev`, `staging`, and `prod` SAM environments via `samconfig.toml` profiles.
- [ ] **Add a Makefile / task runner** — Consolidate common commands (`sam build`, `sam deploy`, `ng serve`, `dotnet test`) into a top-level `Makefile` or `justfile` for a better developer experience.
- [ ] **Export the S3 bucket name** — The `Outputs` section of `template.yaml` currently only outputs the bucket ARN. Also output the bucket name so it can be used directly without parsing the ARN.

### Observability

- [ ] **Add structured logging** — Use `ILogger<S3Controller>` (already available via DI) instead of relying on raw CloudWatch output. Log key events such as presigned URL generation and deletion with request metadata.
- [ ] **Add CloudWatch alarms** — Define basic alarms in `template.yaml` for Lambda errors and API Gateway 4xx/5xx rates.
- [ ] **Enable AWS X-Ray tracing** — Add `Tracing: Active` to the Lambda function in `template.yaml` and add the `Amazon.XRay.Recorder.Handlers.AwsSdk` package to trace S3 calls end-to-end.
